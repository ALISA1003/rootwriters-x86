# 🛡️ RootWriters: Модуль контроля доступа (MAC) для ядра Linux

Учебный проект в рамках курса «Основы математического моделирования в различных операционных системах». 
Данный модуль ядра Linux реализует механизм мандатного контроля доступа (Mandatory Access Control), который ограничивает запись в файлы, принадлежащие администратору (UID=0).

## 📋 Описание проекта

Модуль перехватывает системные вызовы записи на уровне виртуальной файловой системы (VFS) и проверяет права доступа на основе конфигурационного файла `/etc/fsc/rootwriters`. 
В файле хранится "белый список" численных идентификаторов пользователей (UID), которым разрешена модификация root-файлов.

### ✨ Реализованные требования (ТЗ)
- [x] **Отсутствие файла:** Если конфиг отсутствует, ограничений на запись не накладывается.
- [x] **Пустой файл:** Если конфиг существует, но не содержит данных, запись запрещена абсолютно всем.
- [x] **Парсинг:** Корректное чтение численных UID (по одному на строку).
- [x] **Игнорирование мусора:** Модуль автоматически отсекает комментарии (строки, начинающиеся с `#`), пустые строки и любые дополнительные поля после UID (отделенные пробелами или табуляцией).
- [x] **Мгновенное применение:** Ядро отслеживает изменения файла и применяет новые правила "на лету" без необходимости перезагрузки модуля.

## 🛠 Технологии и механизмы

- **Язык программирования:** C (GNU C, Kernel API).
- **Платформа:** Ядро Linux 5.x / 6.x (тестировалось на Ubuntu 24.04 LTS).
- **Архитектуры:** x86_64 (с поддержкой обхода IBT) и ARM64.
- **Инструменты перехвата:**
  - `ftrace` — основной фреймворк для безопасного динамического хукинга функций.
  - `kprobes` — используется для поиска адресов неэкспортируемых функций в современных ядрах.

## 🧠 Архитектура и технические решения

Разработка модуля велась с учетом требований к производительности и безопасности `production`-уровня:

1. **Перехватчик `vfs_write`:**
   Вместо модификации таблицы системных вызовов (`sys_call_table`), модуль использует `ftrace` для подмены функции `vfs_write`. Это позволяет перехватывать попытки записи еще до их обработки конкретными файловыми системами.

2. **Оптимизация производительности (Кэширование):**
   Чтение файла конфигурации при каждой операции `write` привело бы к колоссальному падению производительности ОС. Модуль кэширует список UID в памяти и проверяет метаданные файла (`i_mtime` — время изменения, `i_size` — размер). Чтение с диска происходит *только* в момент изменения конфигурации.

3. **Безопасное выделение памяти:**
   Массивы данных выделяются в куче (`kmalloc_array`), а не на стеке ядра, что предотвращает ошибку переполнения фрейма (`-Wframe-larger-than=`).

4. **Защита от состояния гонки и блокировок (Deadlocks):**
   - **Терминальная защита:** Добавлена проверка `S_ISREG()`, чтобы модуль перехватывал только обычные файлы и не блокировал вывод данных в терминал (tty).
   - **Защита конфигурации:** Добавлено исключение для самого файла `rootwriters`. Это гарантирует, что утилиты (например, `mv`) не потеряют доступ к конфигу при попытке администратора обновить правила.

5. **Совместимость с современными механизмами безопасности (IBT):**
   В код внедрен динамический расчет смещения инструкций для обхода `endbr64` (Indirect Branch Tracking), что предотвращает Kernel Panic на современных процессорах x86_64.

## 🚀 Установка и сборка

### Предварительные требования
Для сборки модуля необходимо установить заголовочные файлы ядра и компилятор:
```bash
sudo apt-get update
sudo apt-get install build-essential linux-headers-$(uname -r)
```

### Компиляция
В директории с исходным кодом (`rootwriters.c` и `Makefile`) выполните:
```bash
make
```

### Загрузка и выгрузка модуля
Для установки скомпилированного модуля в ядро:
```bash
sudo insmod rootwriters.ko
```
Для удаления:
```bash
sudo rmmod rootwriters
```

## 🧪 Тестирование

В состав проекта входит скрипт автоматизированного тестирования `test.sh`. Он проверяет все 7 граничных условий работы модуля, временно понижая привилегии через `sudo -u` и производя запись во временный root-файл.

**Запуск тестов:**
```bash
chmod +x test.sh
sudo ./test.sh
```

**Сценарии тестирования:**
1. Отсутствие файла (ожидается доступ).
2. Пустой файл (ожидается блокировка).
3. Присутствие UID в списке (ожидается доступ).
4. Отсутствие UID в списке (ожидается блокировка).
5. Проверка парсера: игнорирование комментариев и пустых строк.
6. Проверка парсера: игнорирование табуляций и текста (названия отделов).
7. Мгновенное применение изменений при подмене файла.
